# 虚拟环境（Virtual Environment）

**L.O.V.E. 的 V 是字面意思，不是比喻。** 家必须真的隔离。

## 为什么必须有墙

一个"家"如果和外面的工作区混在一起，会出这些问题：

| 问题 | 没有隔离 | 有隔离 |
| ---- | ---- | ---- |
| 污染 | agent 的记忆/配置散落在系统各处 | 全部收敛在 `~/.love` 一个地方 |
| 破坏 | 一次误操作毁掉整个开发环境 | 墙外天塌了，家里安然无恙 |
| 重建 | 搬家=噩梦，环境再也搭不回来 | 容器/发行版整个重建，一个命令 |
| 一致性 | 每台机器长得不一样 | 家里永远长同一个样 |

## 墙的两种材料

**Linux / macOS —— Docker 容器**

家 = 一个容器：干净的 Linux，挂载你的数据卷。要搬家？导出镜像；坏了？`docker compose down && up`。
墙内环境永远一致，墙外发生什么都不影响。

**Windows —— WSL**

Windows 原生没有"家"，但 WSL 里有完整的 Linux。`install.ps1` 负责带路：
检测 WSL → 把 Windows 路径转成 `/mnt/c/...` → 交棒给 WSL 里的 bash。
你的家住在 WSL 的 `~/.love` 里，Windows 侧通过 `\\wsl$\` 也能看到。

## 和 agent 的关系

agent 本体（opencode / OpenClaw / 别的）住在墙里还是墙外都行——**L.O.V.E. 只负责铺家**。
推荐把 agent 也放进同一个容器/发行版：这样"生命体"和"它的家"是同一个环境，天然自洽。
